Code Archaeologist Architecture & Workflow

A complete, deterministic compiler-style pipeline that transforms source code into two queryable graph maps (Structure & Flow), audits them with graph algorithms, and renders an offline single-file viewer.

Two phases, and one hinge between them
Every one of the 28 scripts sits on exactly one side of a single line: BUILD parses source and rewrites artifacts; QUERY reads those artifacts and never opens a source file. That second half is the Zero-RAG guarantee — the reason an agent can answer architecture questions in a fixed-size context instead of reading the repository. check is the hinge: the only command that reads source and writes nothing.
archaeologist.py project | flow | both | report | check | brief
▶ YOUR SOURCE TREE — --src ./backend ./frontend
you run one command; there is only one entrypoint

PHASE 1 · BUILD
Parses source. Rewrites artifacts wholesale — there is no incremental path, by design: node ids depend on the whole corpus.

Stage A — parse: one engine, three producers, seventeen languages
core/grammars.py CORE
Owns "can this machine parse language X": lazy cached parser_for(lang), the version PINS, and the exact pip install for anything missing. A missing grammar warns by name and skips those files — never silently.

parser_for(lang) → a tree-sitter CST per file

Three producers — adding a language is a grammar wheel plus a SPEC row, never a new engine

core/ids.py — SharedNames CORE
Pre-scans every definition from all three producers before any node is built, then qualifies only the names two or more files share — compared case-insensitively, because each note is <id>.md. This whole-corpus dependency is exactly why the build cannot be incremental.

FLOW MAP — methods and functions
extract/build_flow.py EXTRACT
Node per method, overloads included. Resolves a call only when the receiver's type is readable from source; picks an overload by argument count then stated types. What stays ambiguous is dropped and named, never guessed.
→ Click to inspect in sidebar
nodes now exist — only now can a table route find its handler

extract/route_tables.py EXTRACT
Routes declared away from their handler: Django urlpatterns, Rails routes.rb, Laravel routes/*.php, Phoenix routers. It only reads — build_flow calls read(roots) and attaches each route to the one node it names, dropping any reference matching zero or two nodes.
→ Click to inspect in sidebar
routes are read here → frontend fetch linked to backend handler

extract/apply_descriptions.py EXTRACT
The one door AI text enters by, and it is optional: docstring → cached summary whose source hash still matches → deterministic fallback. The build never blocks on it.

Stage C — review passes (report only; everything here needs a built graph and the source)
review/report.py REVIEW
Joins seven passes into data/report/<map>/. One report per map — node ids differ between maps, so a report from the other map must never be embedded.
→ Click to inspect in sidebar
fans out to seven independent passes
↓
analyze.pyREVIEW
Graph-only: cycles, orphans, layer violations, hubs, god objects, and the 0–100 / A–F health score. Degree checks run on app_edges(), which drops test edges.
scan_security.pyREVIEW
Line regex over source; every finding is attributed to the innermost node whose range contains that line — not to the nearest node above it.
metrics.pyREVIEW
LOC, complexity, nesting, params — measured on the graph's own nodes via each node's source+end, so metrics are keyed by graph id by construction.
git_insights.pyREVIEW
One git log --numstat pass → churn, owners, hotspot risk.
debt.pyREVIEW
Comment markers plus orphan nodes and files. A heuristic on purpose — it reports, it does not feed the grade.
tests_map.pyREVIEW
Which nodes a test file names. Also a heuristic, and also kept out of the grade.
duplicates.pyREVIEW
Token-shape hashing (identifiers → ID) so a renamed copy still matches, plus winnowed k-grams for 30-token blocks. Reads ranges from the graph — never re-parses.

Deliberately thin: loads templates/viewer.html, substitutes __TITLE__, __MAPS_DATA__ and the vendored force-graph, and writes one self-contained explorer.html holding both maps. No <script src>, no network, opens from file://.

THE ARTIFACT BOUNDARY — the only thing that crosses
data/structure/graph.json · registry.json · vault/*.md data/flow/flow_graph.json · notes/*.md data/report/<map>/architecture_report.{md,json} · security.json · insights.json data/cache/manifest.json · descriptions.json data/explorer.html
Deterministic by constraint: same source in, same bytes out. No artifact carries a wall-clock time, which is what lets a rebuild be idempotent and a diff be meaningful.
from here on, no script opens a source file
↓
PHASE 2 · QUERY
Reads artifacts. Computes nothing, parses nothing, writes nothing. This is where an agent actually spends its context.
brief→ search / trace / context→
Open a session with the digest, then narrow — each step is bounded in size
review/brief.py REVIEW
1. Orient. The fixed-size digest to open a session with — ~4.3 KB against 13.6 MB of source on a real repository. Anything expensive belongs upstream of it, never inside it.
→ Click to inspect in sidebar
query/search.py QUERY
2. Locate. Filter one graph by name/doc/layer/kind/lang/file, or by --calls / --called-by / --orphans. It exists so nobody greps source to find a starting node.
→ Click to inspect in sidebar
query/trace_path.py QUERY
3. Trace. --from/--to BFS path, --impact-of blast radius, --impact-of-diff to map a git diff onto nodes. Works on either graph.
→ Click to inspect in sidebar
query/context.py QUERY
4. Read. The per-node pack — graph facts plus metrics, risk and insights for one node and its neighbours, rendered under a hard --max-chars budget.
→ Click to inspect in sidebar
A human takes the other exit: open data/explorer.html from file:// — both maps, seven views, no server and no network.
