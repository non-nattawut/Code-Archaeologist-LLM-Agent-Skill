ทำไมไม่ใช้ RAG

RAG หั่นโค้ดเป็นก้อนละประมาณ 500 tokens แล้วค้นด้วยความคล้าย (similarity) ซึ่งทำลายสองสิ่งที่คำถามเชิงสถาปัตยกรรมต้องการพอดี คือ ขอบเขตของหน่วยโค้ด และ ลำดับชั้นการเรียก รอยตัดอาจตกกลางฟังก์ชัน และการค้นด้วยความคล้าย ไม่มีทางรู้ว่าเมธอดหนึ่งเรียกอีกเมธอดหนึ่ง

ความแม่นยำ

โมเดล precision: บอกครั้งเดียวแบบครอบคลุม แล้วระบุชื่อความสูญเสียรายโหนด

ประโยคที่ระบบพูดเสมอ (เก็บไว้ที่ taxonomy.PRECISION_CAVEAT พิมพ์ออกโดย brief และหัวรายงาน) คือ: "call edge เป็นขอบล่าง (lower bound) ในทุกภาษา — จะลาก edge ก็ต่อเมื่ออ่านชนิดข้อมูลของ ตัวรับได้จาก source เท่านั้น กรณีอื่นถูกทิ้ง ไม่ใช่เดา" แต่ละ node จะพกฟิลด์ precision เฉพาะกรณีที่เรียกชื่อความสูญเสียได้ โดยคำนวณจาก edge ที่มีอยู่จริง ไม่ใช่จากภาษาของ node เพียงอย่างเดียว

ค่าเกิดขึ้นเมื่อผลที่ตามมา
interface-dispatch edge ขาออกไปหยุดที่ node ที่เป็น declaration: true (ตัว interface) trace หยุดที่ interface ไม่วิ่งต่อเข้าคลาสที่ implement — เพราะ "อันไหนทำงานจริงตอนรัน" เป็นคำถามที่ type checker ก็ตอบไม่ได้ การเดาหนึ่งอันหรือลากสองเส้นผิดแย่กว่าการหยุดอย่างซื่อสัตย์
overloads การเรียกชี้ไปที่ชุด overload แต่ argument ที่เขียนไว้ใน source ไม่พอจะบอกว่าเป็นตัวไหน การเรียกนั้นถูกทิ้ง และ node ผู้เรียกบันทึกชุดที่กำกวมไว้ในฟิลด์ ambiguous
name-matched node อยู่ในภาษาที่ source มักไม่เขียนชนิดข้อมูลของ receiver ไว้ (JS, TS, JSX, TSX, Ruby, PHP, Elixir, Groovy) การเรียกผ่านอ็อบเจ็กต์ที่ไม่ได้บอกคลาสไว้ถูกทิ้ง — วัดได้จริง: fixture ของ Ruby ทิ้ง @store.save แต่เก็บการเรียกในคลาสเดียวกันไว้ ส่วน fixture ของ TypeScript ที่เขียนคลาสไว้ครบ resolve ได้ 3 จาก 3
# sample_src/services/orders_java/OrderWorkflow.java
private final PricingRule pricing;        // PricingRule เป็น interface
public Order place(OrderRequest request) {
    int total = pricing.price(request);   // impl ตัวไหนทำงาน = เรื่องของ runtime
    return archive.save(request, total);
}

# โค้ดที่คำนวณค่านี้: scripts/core/taxonomy.py
def precision_of(node, targets):
    reasons = set()
    if node.get("lang") in NAME_MATCHED_LANGS: reasons.add("name-matched")
    if node.get("ambiguous"):                  reasons.add("overloads")
    for t in targets:
        if t.get("declaration"):               reasons.add("interface-dispatch")
    return [r for r in PRECISION_REASONS if r in reasons]

ก่อนหน้านี้ค่านี้เคยเป็น approx: true ที่แปะบน Java/Go/C# ซึ่งซื่อสัตย์ดี ตอนที่สามภาษานั้นถูกอ่านแบบข้อความล้วน แต่กลายเป็นการแบ่งแยกที่ไร้เหตุผลทันทีที่ทุกภาษา ย้ายมาใช้ tree-sitter เหมือนกัน — context.py จะย้ำเหตุผลนี้บน node ที่ agent กำลังอ่าน และ explorer แสดงเป็นชิป

เลือกแผนที่ให้ถูก — structure สำหรับ "จัดระเบียบอย่างไร / ใครใช้ X", flow สำหรับ "request เดินทางอย่างไร / อะไรเรียกอะไร"
เริ่มจากกราฟ ไม่ใช่ grep — หา node id ด้วย search.py แล้วหาเส้นทางหรือรัศมีผลกระทบด้วย trace_path.py (อย่าพิมพ์ id จากความจำ เพราะ id อาจถูกเติมชื่อไฟล์นำหน้าเมื่อมีชื่อซ้ำข้ามไฟล์)
ดึงข้อเท็จจริงในครั้งเดียว ด้วย context.py --node <id> แล้วค่อยเปิดโน้ตรายตัวเฉพาะเมื่อยังไม่พอ และเฉพาะ node ที่อยู่บนเส้นทางที่ trace เจอ
คงลิงก์ [[EntityName]] ไว้ในคำตอบ เพื่อให้คำตอบยังเดินต่อได้ ไม่ใช่ข้อความตาย
บอกเสมอว่า edge เป็นขอบล่าง และระบุชื่อความสูญเสียเมื่อ node ระบุไว้ — โดยเฉพาะเมื่อคำตอบทั้งคำตอบวางอยู่บนเรื่อง dead code, blast radius หรือ "ใครเรียกสิ่งนี้"
คำถามว่า "สุขภาพโค้ดเป็นอย่างไร" ให้ตอบจากรายงานที่ generate ไว้ อ่าน architecture_report.md เฉพาะรายละเอียดที่ brief ชี้ไป
คุณภาพภายใน

เครื่องมือที่ทำให้เชื่อผลลัพธ์ได้

เครื่องมือกลุ่มนี้อยู่ใน repo แต่ไม่ถูกติดตั้งไปกับ skill มันมีไว้ตอบคำถามที่ยากที่สุดของเครื่องมือวิเคราะห์: "ถ้าตัวตรวจจับพัง มันจะดูเหมือนโค้ดเบสสะอาด"

เครื่องมือตรวจอะไร
check_graph.py เงื่อนไขที่กราฟถูกต้องต้องเป็นจริงเสมอ กับกราฟใดก็ได้: ทุก edge ต้องลงบน node จริง, id ไม่ซ้ำ, ช่วงบรรทัดของ node ต้องครอบชื่อตัวเองจริง, callee ของ call edge ต้องถูกเอ่ยชื่อในตัวผู้เรียกจริง, ค่า precision ต้องตรงกับสิ่งที่ edge บอก, ตัวเลขในรายงานต้องเป็นตัวเลขของกราฟ, ทุกข้อค้นพบด้านความปลอดภัยต้องอยู่ในช่วงของ node ที่ถูกระบุ, และโน้ตของสอง node ต้องไม่กลายเป็นไฟล์เดียวกันบนระบบไฟล์ที่ไม่แยกตัวพิมพ์
check_graph.py --self-test ทำให้อินพุตพังทีละจุด (หรือสลับฟังก์ชันวิเคราะห์เป็นตัวที่พัง) แล้วบังคับให้แต่ละเช็กต้องดังขึ้น — เช็กที่ไม่มีทางล้มเหลวแย่กว่าไม่มีเช็ก กลุ่ม D ทดสอบการวิเคราะห์แบบ metamorphic: ฉีดวงจร, โหนดกำพร้า, hub, god object หรือการละเมิด layer ลงในสำเนากราฟจริง แล้วต้องรายงานออกมา
check_langs.py ทุกภาษายังสร้างกราฟได้ แต่ละภาษามี fixture ของตัวเอง (store + service ที่เรียกผ่าน field ที่ประกาศชนิด + route + ไฟล์เทส) และตรวจทั้ง node, edge, route, บรรทัด, doc และ metrics — edge คือข้อพิสูจน์ที่สำคัญที่สุด เพราะ node อย่างเดียวพิสูจน์แค่ว่า grammar โหลดได้ แต่ edge พิสูจน์ว่า resolve ตัวรับสำเร็จ ทุก fixture ยังฝัง UTF-8 ขนาด 2, 3 และ 4 ไบต์ไว้ก่อนโหนด พร้อมชื่อ node ที่ไม่ใช่ ASCII หนึ่งตัว เพื่อไม่ให้ byte offset เลื่อนชื่อไปเงียบ ๆ
check_py_oracle.py พาร์สไฟล์ Python ทุกไฟล์ด้วยทั้ง ast และ tree-sitter แล้วล้มเหลวถ้าสองตัวไม่เห็นตรงกันว่ามีอะไรถูกประกาศบ้าง — นี่คือเหตุผลเดียวที่ยังเก็บพาร์สเซอร์ของไลบรารีมาตรฐานไว้
check_regressions.py หนึ่งเคสต่อหนึ่ง "ความล้มเหลวแบบเงียบ" ที่โปรเจกต์นี้เคยเจอจริง รวมถึงการรันรายงานสองครั้งแล้ว diff เพื่อพิสูจน์ว่าไม่มี artifact ไหนแอบใส่เวลานาฬิกาลงไป
check_docs.py ครึ่งที่ตรวจด้วยเครื่องได้ของกฎ "เอกสารเปลี่ยนใน commit เดียวกับพฤติกรรม": ทุกสคริปต์ต้องอยู่ในโครงสร้างของ README และถูกเอ่ยใน CLAUDE.md, ทุกพาธ scripts/... ที่อ้างในเอกสารใดก็ตาม (รวมหน้านี้) ต้องมีไฟล์อยู่จริง, และทุกค่า kind/layer ใน taxonomy.py ต้องมีในเอกสาร TAXONOMY.md
time_build.py จับเวลาจริงต่อขั้นตอนบน corpus ที่กำหนด โดยเปิดอ่านอย่างเดียว
bin/cli.js --self-test ติดตั้ง skill ลงโฟลเดอร์ชั่วคราว ดึง grammar ของตัวอย่าง แล้ว build จริง — และจะล้มเหลวถ้ามี <script src>, <link href> หรือ @import โผล่กลับเข้ามาในหน้า explorer

การตรวจที่แข็งแรงที่สุดคือ ความเท่ากันระดับไบต์: build ใหม่แล้ว git diff บน graph.json กับ flow_graph.json ต้องว่างเปล่า การย้ายพาร์สเซอร์ทั้งสามครั้ง (JS/TS, Python, metrics) พิสูจน์ด้วยวิธีนี้ — ไม่มีไบต์ไหนขยับเลย

สิ่งที่ต้องมีรายละเอียด
Python 3.10+จำเป็น — เป็นตัวรัน pipeline ทั้งหมด
tree-sitter + grammar wheel รายภาษา จำเป็นสำหรับทุกภาษารวมถึง Python ติดตั้งด้วย scripts/core/grammars.py --install [ภาษา] ซึ่งรัน pip install --only-binary :all: --no-cache-dir --target vendor ที่เวอร์ชันซึ่งถูกตรึงไว้ — เป็น wheel ล้วน ไม่ต้องมีคอมไพเลอร์ ลงเฉพาะภาษาที่มีจริง และลงใน <skill>/vendor ไม่ใช่ Python ของคุณ ลบโฟลเดอร์ skill ทิ้งก็หายหมด
gitไม่บังคับ — ใช้เฉพาะฟีเจอร์ churn / ownership / hotspot ถ้าไม่ได้อยู่ใน git repo จะให้ข้อมูลว่างแทนการพัง
