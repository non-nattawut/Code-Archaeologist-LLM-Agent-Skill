Code Archaeologist

A codebase map an AI agent can query instead of reading your whole repo. It scans your code once, builds two graphs plus one note per class and method, then answers architecture questions by walking those graphs — deterministically, with real parsers and no vector database.

The problem

Why not just use RAG?

RAG chops code into ~500-token chunks and retrieves by similarity. That destroys exactly the two things architecture questions are about: scope and call hierarchy. A chunk boundary can land mid-function; a similarity search has no idea that one method calls another.
